
## Assumptions

- The audit brief's repo name and feature list were out of date. Per the owner, the locked spec in the repo (R1.0) is the source of truth, and the audit is measured against it.
- The audited code is `feat/admin-v2` at 630885b, not `main`, because DEC 94 to 99 are only on that branch (PR #36).
- The Quad is audited even though the PRD lists it as R1.1, because it is built and ships behind a per-campus switch.
- Usage model for 5,000 DAU and 500 concurrent: 2 sessions a day of 6 minutes, about 44 API calls per session, a quarter of session time in Inbox or Chat, 0.4 photos per DAU a day, and a launch day of 2,000 sign-ups with 1.3 OTP sends each. The arithmetic is in [E-scalability §3](notes/E-scalability.md).
- Local Docker is not hosted capacity. k6 and Supabase shared 10 cores, and the local Kong gateway caps at 512 connections, so failures above about 500 VUs and the WebSocket failures at scale are local artifacts. The useful output is the ranking of bottlenecks and the per-query costs.
- Free-tier limits come from vendor pages where possible and from secondary sources otherwise. The ones I couldn't verify are marked in [02-research.md](02-research.md): PostHog, EAS Update MAU, the consumer Gmail limit, and whether Supabase counts egress before or after gzip.
- Security pgTAP ran in a scratch clone database (`audit_sec`) so it couldn't block the concurrent load seeding. The load seed was removed afterwards.
- Where no device was available, FPS, startup, memory, VoiceOver and Dynamic Type results come from code review and are marked NOT TESTED.
- Severity: Critical means it breaks at the launch target or breaks a core promise. High means it must be fixed before a public launch. Medium means before scale. Low is cleanup.

## Needs Wasif

1. **Choose a plan direction.** At 5k DAU the DB size (E-03, E-04) and egress (E-20) break the $0 rule even after the fixes. Either cap the launch at about 1k DAU on free tiers, or approve Supabase Pro ($25 a month) when usage reaches about 1k DAU. Both need a DECISIONS_LOG row.
2. **Run the long session and memory test on a device.** `brew install --cask temurin`, build a dev or preview client, then in one terminal `bash audit/scripts/maestro/measure-memory.sh android 35`, and in another `maestro test audit/scripts/maestro/long-session.yaml -e REVIEW_PASSWORD=...`. Run `memory-smoke-3min.yaml` first. It passes if memory plateaus after about minute 10 and grows less than 1.5x by minute 35. Details: [C-memory.md](notes/C-memory.md).
3. **Measure FPS and cold start on Android.** On a release build on a mid-range phone, install Flashlight with `curl https://get.flashlight.dev | bash`, then run `flashlight test --bundleId <android package> --testCommand "maestro test audit/scripts/maestro/memory-smoke-3min.yaml"`, covering a swipe and a feed scroll. Targets: 60 fps, cold start under 2 s, no JS task over 100 ms.
4. **Run a MobSF scan.** `eas build --profile preview -p android`, then `docker run -it --rm -p 8000:8000 opensecurity/mobile-security-framework-mobsf:latest` and upload the APK at localhost:8000.
5. **Check the Supabase Dashboard (staging, then prod).**
   - Auth rate limits and OTP `max_frequency` (set it to 60 s).
   - Custom SMTP rate limit.
   - Realtime "private channels only".
   - Pooler size.
   - Whether the egress meter counts gzip.
   - Mark the 5 "Security Definer View" advisor items as reviewed (A-23, intentional). The fix is to add a pgTAP test pinning each view's columns.
6. **Approve two staging-only tests:** the R2 upload path (E-22) and hosted OTP limits (E-21).
7. **Do the store-console work:** Play Data safety and Apple App Privacy answers (use [B-privacy-compliance.md](notes/B-privacy-compliance.md), including `track_events` per B-01), the review demo account on prod (J-04), and owner items 19 to 21.
8. **Accessibility pass on devices:** VoiceOver and TalkBack on Discover, Sell and Chat, and Dynamic Type at 200%. Check with Xcode Accessibility Inspector and the Android Accessibility Scanner.
9. **Clean up locally when done:** `psql postgresql://postgres:postgres@127.0.0.1:54322/postgres -c "drop database audit_sec"`, and `pnpm install --frozen-lockfile` to remove a stray `node_modules/expo-atlas`.
